Hitagi Engine 线程与主循环

当前引擎只有一个主线程驱动模块 Tick；CPU 并行工作统一进入 core::JobSystem。渲染提交和资源生命周期仍由主/渲染线程控制。

一帧里的执行顺序

这里展示的是控制权流向，不代表所有模块每帧都有实际工作。

1

Main 调用 Engine::Tick()

外部循环负责帧边界，引擎本身不创建主循环线程。

2

RuntimeModule 顺序 Tick

模块按注册顺序执行，避免全局生命周期和 Tick 顺序变成隐式线程问题。

3

ECS / Asset / Physics 提交 CPU jobs

ECS schedule、异步资产导入、Jolt 内部 job 都进入 core::JobSystem。

4

RenderGraph 层内并行录制

先按确定顺序准备 barrier，再把同一 layer 的 pass command recording 发给 workers。

5

渲染线程提交 GPU 队列

queue submit、present、fence signal、transient resource retirement 不放到 worker。

6

Clock 与 FrameMark

Clock::Tick() 更新 delta time，随后记录 Tracy frame mark。

唯一 CPU 边界

core::JobSystem 是 engine-owned worker 池；普通模块不再自己持有 executor 或线程池。

Physics 不自跑循环

PhysicsWorld::Step() 由游戏/模拟逻辑显式调用；Jolt job 只借用 JobSystem。

Render Submit 留主线程

RenderGraph 只并行录制 CPU command context；GPU submit、present 和资源退休留在渲染线程。

Asset 异步可取消

Import*Async() 使用 future 和 cancellation token；AssetManager 析构时等待未完成 jobs。
